# React Native Code Rules

[简体中文](README.zh-CN.md) · **日本語** · [English](README.md)

React Native / Expo プロジェクトで共通して使えるコード生成規約です。本リポジトリでは、コード構造、責務、実装手順、品質基準のみを定めています。具体的な UI、デザイントークン、モーションのパラメーター、ブランドアセット、業務ロジックの実装は提供しません。

現在のバージョン：`0.1.0`

## 対象範囲

本規約は、React Native と Expo を採用するモバイルプロジェクトを対象としています。特に、Figma のデザインから画面を実装し、Expo Router でルートを構成するチームや、複数のアプリでコード構造を統一したいチームに適しています。

この共通パッケージで定める内容：

- `mobile/` の標準ディレクトリ構成
- Page / UI / Controller / Use Case / Model / API / Shared の役割分担
- コンポーネント、ファイル、Props、スタイルの規約
- Expo Router の一般的な構成原則
- Figma の確認、ノード分析、アセットの書き出し、成果物の提出手順
- iOS / Android 両対応、キーボード、モーダル、セーフエリア、アクセシビリティの基準
- パフォーマンス、レンダリング、リスト、画像、リソースのライフサイクルに関する原則
- レイヤー別のテスト、競合状態のテスト、ネイティブ環境での受け入れテスト
- 安全なストレージ、認証、ネットワーク、権限、プライバシーの最低基準
- 依存パッケージ、検証、成果物の提出に関する制約

各アプリで定める内容：

- 色、フォント、余白、角丸、影などのデザイントークン
- モーションの長さ、イージング、画面遷移のパラメーター
- ブランドコンポーネント、画像、SVG、フォントアセット
- 具体的なルートグループ、ルートパス、タブ名
- API、認証、ローカルストレージ、業務の状態管理に関する方針
- 性能上の許容上限、対象端末、プロファイリングツール
- テストランナー、コンポーネントテスト・E2E テストのツール、CI の合格基準
- データ分類、権限、サードパーティ SDK、セキュリティリスクレベル
- Expo / React Native のバージョンと使用を認めるサードパーティの依存パッケージ
- プロジェクト固有の Figma ライブラリ、ファイルやページへのリンク

## 対応言語

- 簡体字中国語：`zh-CN`
- 日本語：`ja`
- 英語：`en`

利用するリポジトリでは、`rules_language` に対応言語を明示し、その言語の `AGENTS` ファイルを参照する必要があります。端末のロケール、ソースコード、ユーザーのメッセージ 1 件だけをもとに、規約の言語を推測してはいけません。

## リポジトリ構成

~~~text
react-native-code-rules/
├── AGENTS.md
├── AGENTS.zh-CN.md
├── AGENTS.ja.md
├── AGENTS.en.md
├── README.md
├── README.zh-CN.md
├── README.ja.md
├── CHANGELOG.md
├── CHANGELOG.zh-CN.md
├── CHANGELOG.ja.md
├── docs/
│   ├── zh-CN/
│   ├── ja/
│   └── en/
└── templates/
    ├── zh-CN/
    ├── ja/
    └── en/
~~~

各 `docs/<言語>/` ディレクトリには、共通の番号 `00`～`12` を付けた規約文書 13 件と、索引の `README.md` があります。プロジェクト固有の規約を記入するテンプレートは、`templates/<言語>/app-specific.md` にあります。

まず対象言語の `AGENTS` ファイルを読み、次に `00` のコアルールを全文読みます。開発規約は、AGENTS ファイルの案内に従って必読の章とタスクに関連する章を読みます。リスクの高いタスクでは、`01`～`12` をすべて読む必要があります。`12` には原文第 13 節のまとめも収録しています。索引を読むだけで本文を読んだことにはできません。

日本語の実行手順は [AGENTS.ja.md](AGENTS.ja.md)、章の対応関係と原文の保持方針は [開発規約の索引](docs/ja/README.md) を参照してください。原文の改訂版 `v2.0（2026-09-04）` とパッケージのバージョン `0.1.0` は別々に管理します。今回の整理に伴うパッケージの公開や自動的なバージョン更新は行いません。

## アプリへの導入

`0.1.0` は現在、`private` に設定しています。npm アカウントの所有者と公開手順が確定する前に、誤ってレジストリに公開することを防ぐためです。まずはローカルパスからインストールして試せます。

~~~bash
npm install --save-dev ../react-native-code-rules
~~~

修正版の `v0.1.0` を GitHub Release として再公開した後は、内容が変わらないタグのアーカイブを HTTPS 経由で取得し、バージョンを固定してインストールできます。

~~~bash
npm install --save-dev https://github.com/LinHaobo0221/react-native-code-rules/archive/refs/tags/v0.1.0.tar.gz
~~~

今後、npm の公開レジストリに登録した後は、すべて小文字のスコープ付きパッケージ名でインストールします。

~~~bash
npm install --save-dev @linhaobo0221/react-native-code-rules@0.1.0
~~~

パッケージをインストールするだけでは、規約は有効になりません。利用するリポジトリの `AGENTS.md` または `mobile/AGENTS.md` に、対象言語のファイルから本パッケージの規約を読むよう、コード生成ツールへの指示を明記する必要があります。

日本語プロジェクトの例（各ファイルをこの順番で全文読む必要があります）：

~~~md
# Mobile 規約入口

rules_language: ja

`mobile/` を変更する前に、次のファイルを順番にすべて読みます。

1. `node_modules/@linhaobo0221/react-native-code-rules/AGENTS.ja.md`
2. `mobile/docs/agents/app-specific.md`
~~~

中国語では `rules_language: zh-CN` と `AGENTS.zh-CN.md`、英語では `rules_language: en` と `AGENTS.en.md` を使用します。

共通規約ではコード構造と品質の最低基準を定め、プロジェクト固有の文書では、そのアプリのデザインと開発に関する事実を記録します。対応するテンプレートをプロジェクトの `mobile/docs/agents/app-specific.md` にコピーし、プロジェクト固有の内容を記入してください。

- [中国語テンプレート](templates/zh-CN/app-specific.md)
- [日本語テンプレート](templates/ja/app-specific.md)
- [英語テンプレート](templates/en/app-specific.md)

## 規約の優先順位

1. 現在のユーザータスクで明示された要件、制約、受け入れ条件
2. 対象ファイルに最も近く、適用範囲内にある `AGENTS.override.md` / `AGENTS.md`
3. コード、設定、API の契約、テスト、承認済みの設計文書など、現在のリポジトリで確認できるプロジェクトの事実
4. 本パッケージの開発規約全体を構成する各文書

コアルールは、コードを書く前に毎回必ず満たすべき条件です。完全版の規約を省略したり、緩めたりするものではありません。具体的な実行手順は、対象言語の `AGENTS` ファイルに従ってください。

プロジェクト固有の規約では、トークン、モーション、採用技術を定められます。ただし、保守性、アクセシビリティ、両プラットフォームの品質について、共通の最低基準を説明なく引き下げるべきではありません。例外が必要な場合は、その理由、適用範囲、受け入れの確認方法を記録してください。

## ドキュメントの検証

```bash
npm run docs:check
npm run pack:check
```

最初のコマンドは、中国語の各文書が保持した原文と一致するかを確認します。あわせて、三言語の構造とコード例、相対リンク、テンプレートも検証します。次のコマンドは、公開せずにパッケージの収録内容を確認します。訳文が原文の意味を正しく伝えているかは、人による確認も必要です。構造の検査だけでは判断できません。

## バージョン方針

- Patch：既存のコード構造に関する要件を変えずに、表現を明確にし、規約間の矛盾を修正
- Minor：互換性のあるルール、任意ディレクトリ、新しい実装チェックの追加
- Major：標準ディレクトリ、役割分担、必読の順序など、互換性を損なう規約の変更

各アプリでは規約のバージョンを固定し、更新時にはプルリクエストで規約の差分を確認してください。意図せず更新される、バージョンを固定しない指定は使わないでください。
