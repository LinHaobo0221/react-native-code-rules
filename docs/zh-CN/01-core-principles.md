# 01 核心原则

> 本文件定义共通规约的目标、适用范围、事实源、任务边界和默认决策方式。

## 目标

在不同 React Native / Expo App 中保持一致的工程结构和代码质量，同时允许每个 App 根据自己的 Figma、品牌、Token、动效与业务需求实现完全不同的视觉和功能。

生成或修改的代码应满足：

- 可以直接进入当前项目，而不是独立 Demo 或无法接入的片段
- 遵守当前项目目录、命名、依赖和技术选择
- 组件职责清楚，便于阅读、测试、审查和后续修改
- 默认覆盖 iOS 与 Android，不以 Web 表现代替原生验收
- Figma 任务尽量忠实还原设计，不自行统一或重设计视觉
- 不在任务范围外扩展业务逻辑、依赖、持久化或基础设施

## 适用范围

本规约适用于：

- React Native / Expo 页面和组件开发
- Expo Router 路由组织
- Figma 设计还原
- 本地 UI 交互实现
- 既有页面重构与共通化
- 移动端 API 接入、状态和数据展示的代码边界
- iOS / Android 平台差异处理

本规约不定义：

- 具体 UI 外观
- Token 数值
- 品牌色和字体
- 动效时长与 easing
- 业务流程、API contract 和数据库结构
- 具体第三方库名单

这些内容必须由使用方项目的 `app-specific.md`、现有代码、Figma 或任务要求提供。

## 开始任务前必须读取的事实源

开始生成代码前，按以下顺序确认事实：

1. 当前任务的明确需求与限制
2. 使用方仓库根目录及 `mobile/` 下的 `AGENTS.md`
3. 本共通规约全部文件
4. 使用方的 `app-specific.md`
5. 当前项目目录、`package.json`、配置、既有组件和测试
6. 若涉及设计，再读取 Figma 节点、截图、变量与资源

禁止只根据过去的回答、缓存摘要或另一个 App 的实现推断当前项目事实。

## 共通规约与项目规约的边界

共通规约规定“如何组织和实现”，项目规约规定“当前 App 具体使用什么”。例如：

- 共通规约要求重复颜色进入 Token；项目规约决定颜色值和 Token 名称。
- 共通规约要求转场语义一致；项目规约决定动画类型、时长和 easing。
- 共通规约要求路由常量集中维护；项目规约决定 route group 和 path。
- 共通规约要求正确映射字体；项目规约决定已加载字体及语言 fallback。

如果项目级规则与共通规则发生冲突：

- 项目级规则可覆盖设计值、依赖选择和项目结构中的明确扩展点。
- 项目级规则不能无说明地降低可访问性、双端兼容、类型安全和可维护性下限。
- 确需例外时，必须记录原因、影响范围、替代方案和验收点。

## 任务范围判断

在动手前先判断任务类型：

### 设计还原

- 以 Figma 和项目 Design Token 为视觉事实源。
- 只实现需求中要求的页面、状态和交互。
- 若用户只要求静态页面或原型，不得擅自接入真实 API、Auth 或持久化。

### 功能实现

- 明确数据来源、状态归属、错误处理和导航边界。
- 不把业务状态塞进展示组件。
- 未经确认不新增 API contract、数据库或本地存储策略。

### 修复或重构

- 先确定根因和受影响范围。
- 保留无关行为，不借机重写整个功能。
- 若问题属于同一 flow、共享壳层或共通组件，必须检查所有直接受影响页面。

### 诊断或评审

- 默认只进行读取、验证和结论说明。
- 未明确要求修改时，不实施修复或创建新架构。

## 保守实现原则

当某项规则、设计或需求不完整时：

- 先检查项目现有实现和项目级文档
- 复用已稳定存在的模式
- 采用最小且可逆的实现
- 不引入新依赖
- 不创造未经确认的业务行为
- 在交付结果中说明假设与偏差

如果不同选择会显著改变产品行为、数据结构、依赖或项目边界，应先请求确认。

## 维护性要求

- 不能以“可以运行”作为完成标准。
- 页面应负责组合，UI 组件负责展示，Hook 负责状态和行为编排。
- 重复实现必须主动评估共通化，但共通化应落在最小合理边界。
- 不为尚未出现的假设需求过度抽象。
- 复杂文件、复杂分支和重复样式应在同一任务范围内适度收口。
- 修改既有代码时必须保留用户和其他开发者的无关改动。

## 同一流程的整体一致性

若问题涉及同一 flow 或共享壳层，例如：

- safe area 与 StatusBar
- Stack / Tabs 层级
- 统一 header 与关闭语义
- 底部操作区
- 键盘避让
- Modal / Sheet 动效
- 列表 loading / empty / error 状态

应检查该流程中所有直接复用此结构的页面。若只修改其中一部分，交付时说明已覆盖和未覆盖范围。

## 文档与代码语言

- 解释语言遵守使用方项目规则；未规定时跟随用户当前使用的语言。
- package 名、route、组件、Hook、类型、字段和错误码保留原始代码形式。
- 注释只解释不明显的设计意图、平台差异和约束，不复述代码表面行为。
