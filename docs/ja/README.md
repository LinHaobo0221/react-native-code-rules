# React Native / Expo 開発規約（分冊索引）

> このディレクトリに、React Native / Expo 開発規約の日本語版全文を収録しています。ディレクトリ構造、コードの層構造、ルーティング、コンポーネント、Figma からコードへの実装手順、両プラットフォームでの操作、パフォーマンス、テスト、セキュリティ、成果物の引き渡しに関するルールを定めています。
>
> React Native / Expo アプリを対象とする規約であり、特定のアプリの業務機能を定義するものではありません。具体的なトークン、ブランドアセット、業務ルール、API、依存関係、Figma ファイルは、引き続き利用側プロジェクトの `app-specific.md` で定義します。

> **改訂版：v2.0（2026-09-04）**
>
> 今回の改訂では、UI と動作ロジックを適切な範囲で共通化すること、ユーザーアクションから業務上の副作用に至る制御フローを明確にすることの 2 点を重点的に強化しました。「作る前に調べる」「変更理由に基づいて抽象化する」「安定して再利用できる最も低い層を選ぶ」「1 つのアクションに 1 つの統括箇所を設ける」「処理を渡すだけの関数を禁止する」「複雑さに応じてパターンを選ぶ」などの厳守ルールを追加しています。

## 文書の位置づけと読み始める場所

- 実行ルールの入口は [AGENTS.ja.md](../../AGENTS.ja.md) です。リポジトリのルートにある [AGENTS.md](../../AGENTS.md) の中国語のルールと内容が一致します。
- タスクごとに、まず [00 コア実行ルール](00-core-rules.md) を全文読みます。その後、入口文書の指示に従って、開発規約の必読分冊とタスクに関係する分冊を読みます。
- `01`～`12` の分冊には、正式な開発規約の全文を収録しています。要約ではなく、この索引を本文の代わりにしてはなりません。各分冊は旧版の同名ファイルを置き換えているため、旧版の分冊を併せて読む必要はありません。
- Feature 横断のリファクタリング、アーキテクチャの調整またはサブシステムの追加、Shared 基盤の変更、認証／セッションの変更、セキュリティに関わる変更、3 つ以上の本番モジュールに同時に影響する変更では、`01`～`12` を全文読まなければなりません。
- レビュー報告、バージョン間の差分、旧索引は、保守や経緯の確認にのみ使います。通常のコード生成で参照するルールには含めません。
- 通常のアプリ開発タスクでは、プロジェクトで指定された言語の版だけを読みます。デバイスのロケール、コードの記述、個々のメッセージから言語を推測しません。リンクは、その文書があるディレクトリを基準に解決します。

## 原文の保持と構成変更について

今回の分冊化には、リポジトリに存在する次の 2 つの最新原文を使用しました。元ファイルは変更せず、保守時の照合用に残しています。実行時に併読する別のルールではありません。

- [react-native-codex-execution-rules.md](../react-native-codex-execution-rules.md)
- [react-native-engineering-standards.md](../react-native-engineering-standards.md)

元の `AGENTS.md` に記載されていた `react-native-expo-core-rules.md` と `react-native-expo-engineering-standards.md` は、実ファイルが存在しない参照名でした。それぞれ `00-core-rules.md` とこの分冊索引に置き換えています。原文第 1.4 節の `docs/codex/react-native-codex-execution-rules.md` も、同じ言語の `00-core-rules.md` を参照するようにしています。

中国語のルール本文で変更したのは、分冊化、各ファイルの先頭見出しの階層、上記のパスだけです。第 1.4 節で従来の全文入りの単一ファイルを指していた「本ファイル」も、全分冊または本共通規約を指す表現に変更しました。条項、リスト、表、例、チェック項目は、追加・削除・書き換えを行っていません。原文冒頭にあった単一ファイルと旧 10 分冊の位置づけの説明は、この索引の現行構成の説明に置き換えています。第 13 節のまとめも省略せず、全文を `12` に統合しました。英語版と日本語版は、同じ構造で項目ごとに翻訳しています。

原文第 1.3 節にある共通規約の優先順位は、記述をそのまま残しています。実行時にルールが競合する場合は、現在の入口文書 `AGENTS` の第 1 節で定めた優先順位に従います。分冊化にあたってルールは書き換えていません。

保守時の検証には、`npm run docs:check`（原文の網羅性、3 言語の構造、コード例、相対リンク）と `npm run pack:check`（パッケージ内容）を使用します。構造の自動チェックだけでは、訳文が原文の意味を正しく伝えているかは確認できません。
